> **Назначение.** Что Антон пишет первой репликой в новом чате, чтобы Claude восстановил контекст и был готов к работе. Промпт **универсальный** — одинаков для всех проектов; `<название>` подставляется при вставке.
>
> **Граница ответственности.** Здесь — только **стартовый промпт**. Как Claude ведёт себя в течение чата (Karpathy, протокол, шорткаты, анти-паттерны) — в `CLAUDE.md`. Методология (фазы, шаблоны пакета, экраны) — в `PROJECT_METHODOLOGY_PLAYBOOK.md`.

> **Когда.** Каждый новый чат — claude.ai / Claude Code / API.

## 2. Express-ускорители (опционально)

> Если стадия уже зрелая (пакет есть) и хочешь сразу в дело — допиши одну из строк в конец промпта §1. Экономит раунд «что делаем».

```

контекста проверь Definition of Ready (зависимости закрыты) и предложи план.
```

**Сразу в дискуссию (без кода):**

```
Хочу обсудить <тема>, в файлах ничего не правим. Дополнительно прочитай
<профильный файл по теме> и проверь DECISIONS.md — нет ли уже решения.
```

## 3. Что Claude делает в ответ

Ветка определяется стадией (детали поведения — `CLAUDE.md` §1):

| Стадия | Признак | Действие Claude |
|---|---|---|
| **Пакет** | есть `NAVIGATION` + `CORE_PRINCIPLES` + `CHECKPOINT_CURRENT` | Прочитать `CLAUDE.md` + 3 файла + N по задаче → саммари «Контекст восстановлен» → ждать |
| **Seed** | есть только `PROJECT_MASTER.md` | Не кодить; предложить разбиение в пакет по playbook |
| **Пусто** | файлов проекта нет | Предложить собрать `PROJECT_MASTER.md` по playbook §4.1 |

Формат саммари (ветка «пакет»):

```
Контекст восстановлен.

📍 Сейчас: <итерация/фаза> (период: YYYY-MM-DD → YYYY-MM-DD)
📊 Прогресс: N/M (~XX%)
🎯 Ближайшая веха: <Alpha / Beta / GA>, ~N недель
🟡 Следующая микро-задача (CHECKPOINT_CURRENT §8): <одна фраза>

Готов работать. Что сегодня делаем?
```

**Без длинного «что я понял».** Если что-то не так (пустой чек-пойнт, задача мимо roadmap, незакрытые зависимости) — остановиться и спросить, не додумывать.

## 5. Полный vs облегчённый пакет (решает первый чат)

> На бутстрапе Claude оценивает масштаб по сигналам и **рекомендует** один из двух пакетов. Выбор — за Антоном. Решение не финальное: облегчённый дорастает до полного по эволюционному закону (playbook §1.3).

**Сигналы (быстрая оценка):**

| Сигнал | → Облегчённый | → Полный |
|---|---|---|
| Поверхности | одна (бот / web / app) | несколько (web + mobile + PWA) |
| Домен | горстка сущностей, 1–2 роли | десятки сущностей, много ролей |
| Интеграции | мало внешних сервисов | много (платежи, фиск, OAuth…) |
| Горизонт | недели, одна фаза | месяцы, Ф1–Ф4 |
| Монетизация | простая / нет | тарифы, unit-экономика, биржа |

Большинство ответов «слева» → **облегчённый**. «Справа» → **полный**. Смешанно → **начать с облегчённого**, разбить позже (триггеры: файл > 1000 строк / факт в 3+ файлах).

**Что в каждом:**

- **Облегчённый (старт для соло-проекта, бота, утилиты):**
  `CORE_PRINCIPLES.md` + `CHECKPOINT_CURRENT.md` + `DECISIONS.md`.
  `NAVIGATION.md` добавить, когда файлов станет > 5. `ROADMAP.md` — когда появятся итерации.

- **Полный (многоповерхностный продукт, как Detailbase):**
  всё ядро ТЗ по playbook §4.2 — `NAVIGATION` + `CORE_PRINCIPLES` + `CHECKPOINT_CURRENT` + `DECISIONS` + `ROADMAP` + `DOMAIN_MODEL` + `USER_STORIES` + `MODULES` + `INTEGRATIONS` + `NFR` + `ANALYTICS` + профильные.

Во всех вариантах ядро (`CLAUDE.md` + `CHAT_HANDOFF.md` + `PROJECT_METHODOLOGY_PLAYBOOK.md`) — одинаковое.
