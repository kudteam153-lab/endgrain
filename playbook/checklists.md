## Чек-лист старта нового проекта (для Антона)

### День 1–7. Research
- [ ] 5–10 customer development интервью
- [ ] Конкурентный анализ
- [ ] Сохранить как `Research_Report.md`
- [ ] Гипотеза в 1 абзаце

### День 8–14. Seed
- [ ] Создать Project в Claude
- [ ] Загрузить `Research_Report.md` в Project Files
- [ ] Создать `PROJECT_MASTER.md` по `package-templates.md §Seed`
- [ ] Прогнать через Claude 3 ревью на противоречия
- [ ] Сохранить `BRAND_GUIDELINES.md` (если есть)
- [ ] Добавить memory-сниппет (см. ниже) в User Memories
- [ ] Скопировать `CLAUDE.md` + `CHAT_HANDOFF.md` + `playbook/` + `.claude/` в проект

### День 15+. ТЗ
- [ ] Создать `NAVIGATION.md`, `CORE_PRINCIPLES.md`, `CHECKPOINT_CURRENT.md`
- [ ] Идти по 13 разделам ТЗ — каждый = серия чатов
- [ ] После каждого утверждённого раздела — профильный файл
- [ ] Поддерживать `DECISIONS.md` непрерывно

### Когда ТЗ закрыто
- [ ] Создать `DESIGN_SYSTEM.md`
- [ ] Создать `SCREENS_CHECKPOINT.md` + `SCREENS_WEB.md`
- [ ] Заполнить `.claude/design-tokens.json` токенами из DESIGN_SYSTEM
- [ ] Начать проектирование экранов по 17-секционному шаблону

### Когда экраны утверждены
- [ ] Запустить И-0 разработки
- [ ] Заполнить `CHECKPOINT_CURRENT.md §8` первой микро-задачей
- [ ] Каждые 2 недели — закрывать итерацию, `CHECKPOINT_ITERATION_N.md`

### Гейт безопасности — до первого реального юзера (обязательно)
> Agentic-код работает ≠ безопасен. Уязвимость не видно, пока не эксплуатнули — естественного фидбэка нет. Это минимальный порог ответственности перед релизом.
- [ ] Прогон через `/security-review` (или Claude с брифом): аутентификация и сессии, утечки данных в API-ответах, валидация ввода и инъекции, зависимости с известными CVE
- [ ] Каждую находку — оценить «фикс / приемлемо»; **человеческое ревью** для всего, что трогает аутентификацию, секреты, данные
- [ ] Помнить: AI-скан — помощник, не замена security-тулинга и человека на высоких ставках

### Гейт PMF — до выхода из MVP
> Детали и litmus-тесты — `playbook/phases.md §Гейт PMF`.
- [ ] Метрики и ложные позитивы определены **до** первого юзера
- [ ] Sean Ellis >40% «очень расстроюсь» ИЛИ effort-тест пройден (продукт «тянет», а не «толкаем»)
- [ ] Паттерн держится ≥3 итерации, не разовый всплеск

## Health-чеки пакета {#H}

### Раз в итерацию (Антон + Claude)
- [ ] `CHECKPOINT_CURRENT.md` отражает текущую итерацию
- [ ] `SCHEMA.md` синхронизирована с реальной БД
- [ ] `ROADMAP.md` — статусы US актуальные
- [ ] `DECISIONS.md` — все решения за итерацию зафиксированы

### Раз в квартал
- [ ] Cross-refs работают (нет битых ссылок)
- [ ] Не появилось дублирования между файлами
- [ ] `NAVIGATION.md` отражает реальную структуру

### Сигналы рефакторинга
- 🚩 Файл > 1000 строк → дробить
- 🚩 Один факт в 3+ файлах → выбрать canonical
- 🚩 Claude в новом чате путается → проблема в `CHECKPOINT_CURRENT.md`

## Уроки Detailbase (что улучшить в следующий раз)

| Урок | Применение |
|---|---|
| Seed вырос до 2000 строк до разбиения | Дробить при ~800 строк |
| 17-секционный шаблон появился не сразу | Создавать **до** первого экрана |
| `DECISIONS.md` добавили в середине | Заводить с первого дня |
| Cross-refs ломались | С первого дня — якоря в фигурных скобках |
| Stage-by-stage HTML-мокапы работают | Сложный экран — 4–5 stage с ревью |
| Browser quirks копятся как актив | Отдельный раздел в `DESIGN_SYSTEM.md` |
| Day + night mode с первого экрана | Не доделывать тёмную тему «потом» |
| Mobile-thumb-zone | Зашить в `CORE_PRINCIPLES §3` |
| NSM утвердить рано | Без неё метрики хаотичны |
| Out of Scope явно | Спасает от scope creep |
| Security откладывали на «потом» | Гейт безопасности — до первого юзера, не перед прод |
| Раннюю traction путали с PMF | Litmus-тесты (Sean Ellis / effort) до выхода из MVP |

## Прецеденты и FAQ

| Ситуация | Действие |
|---|---|
| Claude путается | «Перечитай `CHECKPOINT_CURRENT.md` и `NAVIGATION.md`» |
| Решение против принципов | «Противоречит принципу №X в `CORE_PRINCIPLES`. Пересмотр — через `DECISIONS.md`» |
| Не знает, какие сущности | «Смотри `DOMAIN_MODEL.md #Entity`» |
| Чат длинный, контекст уплывает | Завершить задачу, обновить чек-пойнт, новый чат |
| Хочет править несколько модулей | «Разбей на задачи, делай по одной» |
| Продуктовое обсуждение без кода | Шаблон дискуссии из `CHAT_HANDOFF.md §2` |

## Сигнальная таблица

| Сигнал | Значение | Действие Claude |
|---|---|---|
| «..» в начале | Нужно уточнение | 1 вопрос с A/B/C |
| «A, B, C» | Просит варианты | 3 альтернативы, не выполнять |
| «ок» | Подтверждение | Зафиксировать, двигаться |
| «стоп» | Прекратить | Прекратить, ждать |
| Скриншот ошибки | Bug-репорт | Воспроизвести, найти причину, не чинить без ok |
| Не нашёл в файлах | Пробел в доке | Спросить, не додумывать |
| Решение задевает 3+ файла | Архитектурное | Запись в `DECISIONS.md` обязательна |
