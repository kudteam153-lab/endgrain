## Журнал решений (DECISIONS.md)

**Append-only.** Решения не удаляются. Пересмотр = новая запись со ссылкой на отменяющую старое; старое получает `❌ отменено через #D-XX`.

**Формат записи:**

```
## D-XX · YYYY-MM-DD · <короткий заголовок>
- **Решение:** что в итоге
- **Было / альтернатива:** от чего отказались
- **Причина:** почему такой выбор
- **Затрагивает:** файлы / модули / US / сущности
- **Статус:** ✅ применено / 🔄 пересмотр / ❌ отменено через #D-YY
```

**Когда заводить:** изменение, требующее правок в нескольких файлах; выбор между 2+ архитектурными альтернативами; отмена ранее принятого; продуктовое/коммерческое решение, влияющее на код.

**Когда НЕ заводить:** реализационные детали без альтернатив (имя переменной, структура папок); решения внутри одного PR; косметика.

## Стандарт cross-refs (единый для всех файлов) {#crossrefs}

| Что | Формат | Пример |
|---|---|---|
| Файл целиком | `FILENAME.md` | `см. INTEGRATIONS.md` |
| Раздел | `FILENAME.md §X.Y` | `см. NFR.md §4.2` |
| Якорь сущности | `FILENAME.md #Entity` | `см. DOMAIN_MODEL.md #OrderQuote` |
| User Story | `#US-XXX` | `см. USER_STORIES.md #US-101` |
| Модуль | `#М-XX` | `см. MODULES.md #М-07a` |
| Интеграция | `#I-XX` | `см. INTEGRATIONS.md #I-06` |
| Решение | `#D-XX` | `см. DECISIONS.md #D-44` |
| Экран | `#SCR-WEB-XX` | `см. SCREENS_WEB.md #SCR-WEB-05` |

В заголовках с русским текстом — явные якоря в фигурных скобках:
```markdown
### US-101 — Альтернативное КП после отказа {#US-101}
```

## Итерации

**Длительность.** Режим «соло-продакт + Claude, 2–5 ч/день»: **2 недели ≈ 35 Claude-часов** — 1 крупный модуль или 2–3 мелких. Каждые 2 недели — чистый чек-пойнт.

**Структура CHECKPOINT_CURRENT.md** (полный шаблон — отдельная болванка `CHECKPOINT_CURRENT.md`):

```
§1 Текущее состояние [REQUIRED]
§2 Что сделано (модули прод/staging, в работе, US закрыто, архив) [REQUIRED]
§3 Текущая итерация (цель, в работе 🟡, завершено ✅, под риском 🔄) [REQUIRED]
§4 Изменения в БД [REQUIRED]
§5 Изменения в API [optional]
§6 Архитектурные решения [optional]
§7 Тех-долги, баги, риски [optional]
§8 Следующая микро-задача [REQUIRED] — самый важный раздел
§9 Связанные артефакты (git hash, staging URL)
§10 Что НЕ менять без явного запроса Антона
```

## Definition of Ready (DoR) — задача готова к старту {#dor}

- [ ] Описана в `ROADMAP.md` с конкретным acceptance.
- [ ] User Story утверждена в `USER_STORIES.md` (если применимо).
- [ ] Сущности описаны в `DOMAIN_MODEL.md`.
- [ ] Зависимости от других задач завершены.
- [ ] Нужны новые поля → миграция запланирована.
- [ ] Антон явно подтвердил приоритет.

## Definition of Done (DoD) — задача завершена {#dod}

- [ ] Acceptance criteria из `CHECKPOINT_CURRENT.md §8` выполнены.
- [ ] Код прошёл review (свежим чатом Claude).
- [ ] Миграции применяются и откатываются.
- [ ] Unit-тесты покрывают ключевые ветки.
- [ ] `CHECKPOINT_CURRENT.md` обновлён.
- [ ] Решения (если были) в `DECISIONS.md`.

## Definition of Done — итерация

- [ ] Все задачи итерации ✅ либо явно перенесены.
- [ ] Демо на staging работает end-to-end.
- [ ] Архив итерации создан. Два основания на выбор, смешивать осознанно: снимок итерации `CHECKPOINT_ITERATION_N.md` (по времени) либо единый `CHECKPOINT_ARCHIVE.md` (по жизненному циклу — закрытое из любого раздела). Второе выигрывает, когда закрывается не итерациями, а трек за треком.
- [ ] `CHECKPOINT_CURRENT.md` обнулён под следующую итерацию.
- [ ] Retrospective: что не предусмотрели → запись в `DECISIONS.md`.
