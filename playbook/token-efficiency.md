# playbook/token-efficiency.md — эффективность контекста и кэша

> Reference-кусок playbook. Читается, когда строишь агентов/инструменты в своих продуктах (VPN-бот, Detailbase API, Telegram-ассистент) или оптимизируешь стоимость. Возврат к ядру — `PROJECT_METHODOLOGY_PLAYBOOK.md`.
>
> Источник: сессии Code w/ Claude 2026 (Brad Abrams — prompt caching; Noah Zweben — форма данных; Daisy Hollman — «контекст это фиксированный ящик»).

---

## Принцип

Окно контекста не растёт уже больше года и не вырастет скоро. Главный навык — не «впихнуть больше», а класть в фиксированный ящик только нужное. Две оси экономии: **кэш** (платить меньше за повторяющийся префикс) и **форма данных** (сами данные компактнее).

---

## 1. Prompt caching — цель ≥ 80% hit rate

В проде агентов (твои боты на anthropic SDK) добивайся минимум 80% попаданий в кэш; зрелые продукты держат 90+. Кэш дешевле, быстрее и не считается в rate-limit.

**Три правила (Brad Abrams):**

1. **Стабильный префикс.** Системный промпт + описания инструментов + неизменный контекст — в начале, одинаковым байт-в-байт между запросами. Любое изменение в начале рушит кэш для всего, что после.
2. **Не держи неиспользуемые схемы инструментов.** Подключил 20 инструментов «на всякий» → платишь за их описания каждый ход. Оставляй только нужные задаче.
3. **Не держи сырой вывод инструментов в контексте.** Большой JSON-ответ от tool'а не оставляй целиком — извлеки нужное, остальное выкинь. Программный вызов: пусть модель пишет код, который инспектирует результат и берёт только необходимое.

**Как измерять.** В ответах API есть `usage.cache_read_input_tokens` и `usage.cache_creation_input_tokens`. Hit rate ≈ `cache_read / (cache_read + cache_creation + обычные input)`. Скрипт-агрегатор по логам — `.claude/scripts/cache_report.py`.

**Что кэшировать в твоих ботах:** системный промпт, инструкции, статичный справочный контекст (прайс, FAQ-база). Маркируй их как кэшируемые; динамику (сообщение пользователя) — после.

---

## 2. Форма данных, не только объём

Один кейс с конференции: компания срезала расход токенов на 66%, **переключив вывод инструмента с JSON на markdown, убрав лишние поля и таймстемпы** — и это не только удешевило, но и улучшило результаты модели.

**Правила для tool-выводов и MCP-инструментов, которые ты пишешь:**

- **Markdown вместо JSON**, где модель просто читает результат. JSON тратит токены на скобки, кавычки, повторяющиеся ключи. Таблица/список в markdown компактнее и читается моделью лучше.
- **Убирай поля, которые модель не использует.** Внутренние id, метаданные, аудиторские таймстемпы — если они не нужны для решения, не отдавай их в контекст.
- **Убирай таймстемпы**, если задача не про время. Они почти не несут смысла для модели, но раздувают вывод.
- **Сворачивай повторяющееся.** 200 объектов с одинаковой структурой → markdown-таблица с шапкой один раз, а не 200 раз ключи.
- **JSON оставляй только там, где он реально парсится кодом** (structured output, который ты потом `json.loads`). Для «модель прочитает и решит» — markdown.

## Связь с системой

- Это применяется к **твоим продуктам** (боты, API), а не к работе Claude Code над проектом.
- Для самой работы Claude Code принцип «стабильный префикс» означает: не дёргай `CLAUDE.md`/playbook без нужды — стабильный системный слой хорошо кэшируется (минимум кэша на 4.8 снижен до 1024 токенов, так что кэшируется даже короткое).
- Прогрессивное раскрытие (`package-templates.md`) — это та же экономия, но на уровне документации пакета.
