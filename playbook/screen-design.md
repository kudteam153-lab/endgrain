## A11y — чеклист §12 {#a11y-checklist}

Раскрытие секции §12 шаблона. Не «помнить», а **проверяемый инвариант экрана** — как токены. Платформо-независимо (web + Compose); где термины расходятся — мапа в скобках.

**Восприятие**
- Контраст текст/фон ≥ **WCAG AA**: 4.5:1 обычный текст, 3:1 крупный (≥24px / ≥18.66px bold) и иконки-смысл. Брать из токенов, не на глаз.
- Смысл не передаётся **только цветом** (ошибка/успех — ещё иконка/текст, не один красный).
- Экран не разваливается при **зуме 200%** (web) / `fontScale 1.3` (mobile — см. cross-ref ниже).

**Управление**
- Всё интерактивное достижимо с **клавиатуры** (web) / фокус-навигацией и switch-access (mobile); логичный **tab/focus order**.
- **Фокус виден** всегда (focus-visible ring / системный focus indicator). Не убирать индикатор фокуса.
- Icon-only контролы имеют текстовую метку (`aria-label` web / `contentDescription` Compose). Декоративное — наоборот, скрыто от screen reader.

**Формы и динамика**
- Каждое поле связано с лейблом; ошибка **ассоциирована с полем** (`aria-describedby`+`aria-invalid` / `Modifier.semantics{ error() }`), а не висит отдельным текстом.
- Обязательность передана не только звёздочкой (текст «обязательно» для screen reader).
- Динамические обновления (тосты, инлайн-валидация, live-счётчики) анонсируются **live-region** (`aria-live` / `liveRegion` semantics).

**Движение**
- Уважать **reduced-motion** (`prefers-reduced-motion` / системный «убрать анимацию»): отключить нефункциональную анимацию, не ломая навигацию.

**Mobile-специфика — не дублировать, см. `skills/design-anti-patterns` (раздел Mobile):** тач-таргет ≥ 48dp, инсеты под статус-бар/жестовую зону, развал на `fontScale 1.3`, тёмная тема ≠ механическая инверсия. Здесь — только cross-ref, канон там (§4.5).

**Тест применения:** пункт нарушен в основном потоке экрана → **BLOCKER**; во вторичном → **MAJOR**. Механически контраст-токены ловит хук `design-check`; суждение поверх — агент `design-reviewer` (CLAUDE.md §12) судит по этому чеклисту.

## Протокол работы над экраном

1. Создать запись в `SCREENS_<surface>.md` со статусом ⏳.
2. Чат: прочитать `DESIGN_SYSTEM.md` + `SCREENS_CHECKPOINT.md` + связанные US/модули.
3. Заполнить 17 секций последовательно.
4. Создать HTML-мокап (отдельный файл). Сложный экран — 4–5 stage сборки с промежуточным ревью.
5. Антон смотрит → правки → ✅.
6. Обновить прогресс в `SCREENS_CHECKPOINT.md`.

## Что Claude НЕ делает в дизайне

- Не выдумывает компоненты — нет в `DESIGN_SYSTEM.md §8` → пишет в Open questions.
- Не выдумывает endpoints — нужен → заявляет явно, ждёт решения.
- Не выдумывает UX-текст — использует словарь.
- Не пропускает секции шаблона — каждая обработана: заполнена либо `N/A` + причина.
- Не начинает следующий экран, пока текущий не ✅.
- Не хардкодит цвета/размеры — только токены (проверяется хуком design-check; см. `CLAUDE.md §10`).
