## Во время работы

**Перед началом задачи:**
1. Найти задачу в `ROADMAP.md`.
2. Проверить DoR (см. `decisions-and-iterations.md §DoR`).
3. Проверить в `CHECKPOINT_CURRENT.md`, что зависимости завершены.
4. Что-то не так → сообщить Антону **до** начала.

**В процессе:**
- Не делать изменений вне scope. Баг в чужом модуле → отдельная задача, не «заодно».
- Conventional commits: `feat(М-02): add OrderQuote versioning`.
- Не пересматривать решения молча.

---

## Пересмотр решения

1. Остановиться.
2. Сказать: «Возникла ситуация, требующая пересмотра `#D-XX`».
3. Объяснить, что меняется и почему.
4. После согласования — новая запись `#D-YY` в `DECISIONS.md` со ссылкой на `#D-XX`.
5. Старое решение → статус `❌ отменено через #D-YY`.
6. Обновить затронутые файлы.
7. Проверить уже написанный код на соответствие новому решению.

---

## Завершение задачи

1. Code review через Claude **в свежем чате** (другой контекст — антипредвзятость).
2. Антон — final approval.
3. Merge.
4. Обновить `CHECKPOINT_CURRENT.md` §1, §2.3, §3.3, §4, §8 (можно через `/checkpoint`).
5. Если задача затронула API → §5. Если было решение → §6 + `DECISIONS.md`.
6. Закрытое не оставлять в рабочем файле: исполненный §8-блок, прошлые записи §1/§2.3 — в архив тем же прогоном. Иначе чек-пойнт копит историю и через полгода перестаёт читаться за один вызов.

> **Если чек-пойнт всё же разбух** (не влезает в один `Read`, съедает бюджет старта) — раскладка по жизненному циклу: `CURRENT` (состояние + следующая задача) · `DEBT` (открытый долг) · `API` (контракты, миграции) · `ARCHIVE` (закрытое). Payload §4/§5/§7 уезжает, **заголовки остаются со строками-указателями**: экстракторы разделов обычно читают «от `## N.` до `## N+1.`» и при пропаже заголовка молча отдают файл до конца. Инструмент — `.claude/scripts/rotate_checkpoint.py` (dry-run, два доказательства целостности, словари разметки настраиваются под проект). В Detailbase так сделано после того, как файл дорос до 773 КБ.

## Если контекст близок к лимиту

| Категория | Что делать |
|---|---|
| Всегда в контексте | `NAVIGATION.md`, `CHECKPOINT_CURRENT.md` |
| По задаче | Файлы из маршрутизации — прочитал, использовал, выгрузил |
| Точечно, не целиком | Реестр долга (`grep` по модулю), справочник контрактов — при правке endpoint |
| Не загружать без нужды | Архивные чек-пойнты, `SCHEMA.md` целиком, `USER_STORIES.md` целиком, reference-куски playbook наперёд |

## Антипаттерны процесса

Полный список анти-паттернов поведения — `CLAUDE.md §8`. Специфичные для процесса разработки:

❌ Писать код, не прочитав чек-пойнт и roadmap.

❌ Завершать задачу без обновления `CHECKPOINT_CURRENT`.
❌ Молча менять решения вместо процедуры пересмотра выше.
