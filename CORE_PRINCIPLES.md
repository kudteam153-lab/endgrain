## 1. Видение и рыночная гипотеза `[ЯДРО]`

- **Для кого:** столяр-любитель с мастерской — циркулярка, струбцины, шлифмашина. Умеет делать, не умеет придумывать узор и считать раскрой.
- **Какую боль решает:** две разом. Придумать узор, который не выйдет кашей, и получить план, по которому доска соберётся именно такой, как на превью, без пересчётов на салфетке.
- **Почему это работает:** калькуляторы раскроя уже есть и бесплатны (`DECISIONS.md #D-02`). Чего нет — генерации узора поверх модели, которая физически реализуема по построению. У конкурентов слои задаются руками, поэтому генерировать им нечего.
- **Проверка гипотезы:** acceptance в `GOAL.md` — столяр, не видевший кода, собирает доску по PDF, и она совпадает с превью.

## 2. Стратегические принципы (что НЕ нарушаем молча) `[ЯДРО]`

1. **Неизготавливаемое состояние невыразимо.** Всё, что можно собрать в интерфейсе, можно собрать на верстаке. Достигается моделью операций (`#D-01`), а не проверками поверх картинки. Появилось состояние, которое рисуется, но не режется — это баг модели, а не недостающая валидация.
2. **Расчёты выводятся из состояния, а не пишутся рядом.** Кут-лист, объём, отходы, текст инструкции — функции от стека операций. Отдельный код, считающий то же самое вторым способом, рано или поздно разойдётся с превью и соврёт в мастерской.
3. **Детерминированность по seed.** Одна ссылка — одна доска, всегда. Без этого не работает ни шаринг, ни «дай ещё 12 вариантов», ни воспроизведение чужого результата.
4. **Числа предметной области — из `FACTS.md`, не из головы.** Пропил, припуски, запас материала выдуманы уже один раз, в ресёрче. Переизобретать их по ходу — портить заготовку чужими руками.
5. **Срок не двигается — двигается скоуп.** Порядок реза задан заранее (§4.3). «Успеем, если поднажать» — не решение.

## 3. UX-принципы `[ЯДРО]`

- **Один экран.** Ручки слева, доска справа, PDF одной кнопкой. Мастер-визард, вкладки и модальные шаги не заводить: жюри смотрит минуту, столяр — тридцать секунд.
- **Пересчёт мгновенный.** Поменял размер, породу, пропил — узор и цифры обновились сразу, без кнопки «применить».
- **Первое действие — «сгенерировать».** Пустой экран с формой на двадцать полей проваливает acceptance №1. Доска на экране есть до того, как что-то настроили.
- **Мобильная вёрстка — «не разваливается»** и не более того (`GOAL.md §Anti-scope`).

## 4. Архитектура ядра и стек `[ЯДРО]`

### 4.1. Архитектурный принцип №1 (что мы НЕ делаем)

**Не заводим сервер.** Ни для галереи, ни для аккаунтов, ни для рендера PDF (`#D-03`). Всё считается в браузере, состояние живёт в localStorage и URL-хеше. Сервер стоит день из семи, не влияет ни на один критерий жюри и добавляет единственный способ упасть ровно в момент проверки.

**Не заводим солвер.** Гибрид «нарисовал картинку — программа подобрала распил» — задача поиска, в неделю не влезает (`#D-01`).

### 4.2. Технологический стек

| Слой | Чем | Почему |
|---|---|---|
| Сборка | Vite + TypeScript | статика, мгновенный дев-сервер, деплой одной командой |
| UI | React | один экран, состояние в хуках, без роутера и стора |
| Ядро | `src/core/` — чистый TS без зависимостей от React | тестируется юнит-тестами, переносится в воркер, если понадобится |
| Рендер узора | SVG | детерминированный, экспортируется как есть, масштабируется в PDF |
| 3D-превью | three.js | `#D-04`, экструзия полигонов на толщину доски |
| PDF | клиентская генерация | сервера нет; библиотека выбирается на дне 5 |
| Тесты | vitest | ядро без DOM, раннер должен стартовать за секунды |
| Хостинг | статический | ссылка обязана открываться у жюри без прогрева |

### 4.3. Порядок реза скоупа под срок

Режем в этом порядке, сверху вниз. Список закрыт — расширять его в последний день нельзя.

1. Оптимизация раскроя 1D (и так «только если остаётся день», `#D-04`)
2. Скрещивание двух seed'ов
3. Библиотека шаблонов
4. 3D-превью целиком
5. Шеврон и ёлочка (`angleDeg != 90`)

**Что не режется ни при каких условиях:** PDF-инструкция. Без неё отваливается главный критерий жюри и acceptance №3–4 — остаётся красивая картинка, каких на конкурсе будет много.
