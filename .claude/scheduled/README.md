# .claude/scheduled/ — рутины по расписанию

Здесь остался **один** скрипт: `memory-hygiene.sh`.

## Что было и почему убрано

`nightly-deps.sh` (ночной аудит CVE) и `checkpoint-drift.sh` (проверка дрейфа чек-пойнта) удалены 2026-07-26: **ноль запусков за всю историю**.

Писались они под cron на Linux-сервере, а работа идёт на Windows, где cron нет. Скрипт, который невозможно запустить в своей среде, — не страховка, а её видимость: в `CLAUDE.md` он числился рутиной, на диске лежал, и ни разу не отработал.

Идея верная — повторяющиеся проверки должны идти по расписанию, а не держаться в голове. Но реализовывать её надо тем, что здесь работает.

## Что осталось

`memory-hygiene.sh` — гигиена над-проектной памяти: свежесть `PORTFOLIO.md`, размер `JOURNAL.md`, дубли заголовков записей. По умолчанию режим отчёта, ничего не двигает. Ротация прошлых месяцев в `journal/YYYY-MM.md` — только по флагу, с бэкапом.

```bash
bash .claude/scheduled/memory-hygiene.sh            # отчёт
bash .claude/scheduled/memory-hygiene.sh --rotate   # + вынести прошлые месяцы
```

Запускался 4 раза вручную и остаётся, потому что его находки реальны: дубли в `JOURNAL` — ровно то, что он ищет, и к моменту разбора их накопилось 10 (сняты 2026-07-26 вместе с починкой `session-log.sh`).

## Чем заменить расписание на Windows

| Способ | Когда подходит |
|---|---|
| `/loop <интервал>` в сессии | разовое во время работы: «опрашивай билд каждые 5 минут». Умирает вместе с сессией |
| Планировщик заданий Windows | постоянные локальные рутины, переживает перезагрузку |
| Канарейка в `SessionStart` | проверки, которые должны идти при каждом старте |

Третий вариант закрыл задачу «проверять предохранители регулярно» лучше, чем cron: проверка идёт в каждой сессии, и результат виден в первой реплике, а не в логе, куда никто не смотрит.

## Безопасность

Агент, работающий по расписанию без человека, — заметная поверхность атаки. Минимальный набор разрешений, обёртки под git, вывод в лог. Ничего, что пишет в прод без проверки, на расписание не вешать.
