# Гейт перед merge

Оценка риска по тронутым путям и рекомендованные ревьюеры:

!`python3 .claude/scripts/assess_risk.py ${ARGUMENTS:+--base $ARGUMENTS}`

## Зачем две оси

Изменение может пройти одну проверку и провалить другую:

- Код следует всем принципам, но реализует не то, о чём просила задача → **Стандарты ✅, Спека 🔴**.
- Код делает ровно то, что просили, но ломает конвенции проекта → **Спека ✅, Стандарты 🔴**.

Поэтому оси считаются **раздельно и не переранжируются между собой**. Слияние в один список даёт эффект, ради предотвращения которого разделение и существует: сильная находка по одной оси маскирует провал по другой.

## Порядок

### 1. Зафиксировать точку сравнения

База — из `$ARGUMENTS`, иначе `main`. Проверить, что ссылка резолвится (`git rev-parse`) и diff непустой, **до** запуска субагентов: битая база не должна всплывать внутри двух параллельных контекстов.

Диффы: `git diff <база>...HEAD` (три точки — от merge-base), список коммитов `git log <база>..HEAD --oneline`.

### 2. Найти источник спеки

По порядку: задача из `CHECKPOINT_CURRENT.md` §8 → `GOAL.md` (acceptance + anti-scope) → запись `#D-XX` в `DECISIONS.md`, если правка сделана по решению → путь, переданный аргументом. Ничего не нашлось — спросить. Спеки нет — ось Спека пропускается с явной отметкой, а не молча.

### 3. Запустить ревьюеров

Из рекомендации `assess_risk.py`: `code-reviewer` всегда, `security-reviewer` и `design-reviewer` — если в списке. Параллельно, одним сообщением.

**Ось Стандарты** ведёт `code-reviewer`. Ему передать: команду диффа, список коммитов, `CORE_PRINCIPLES.md`, действующие `#D-XX` из `DECISIONS.md` и базовый список запахов ниже целиком — своего доступа к нему у субагента нет.

**Ось Спека** ведёт отдельный вызов `code-reviewer` с другим брифом: acceptance и anti-scope из `GOAL.md`, текст задачи. Отчёт по трём пунктам — (а) требования спеки, реализованные частично или не реализованные; (б) поведение в диффе, которого никто не просил; (в) требования, которые выглядят сделанными, но сделаны неверно. Каждую находку подкрепить цитатой из спеки.

### 4. Базовый список запахов (ось Стандарты)

Применяется поверх того, что документирует проект. Два связывающих правила:

- **Проект перебивает.** Документированное правило проекта всегда сильнее; там, где оно разрешает то, что список бы отметил, — молчать.
- **Всегда суждение.** Каждый пункт — помеченная гипотеза («похоже на Feature Envy»), не нарушение. Что ловит линтер или форматтер — пропускать.

| Запах | Что это | Куда чинить |
|---|---|---|
| Загадочное имя | имя не раскрывает, что делает или хранит | переименовать; честного имени нет — дизайн мутный |
| Дублирование | одна и та же форма логики в разных местах диффа | вынести общее, звать из обоих |
| Feature Envy | метод лезет в чужие данные чаще, чем в свои | перенести метод к данным |
| Група данных | одни и те же поля ездят вместе | завести тип, передавать его |
| Одержимость примитивами | строка или число вместо доменного понятия | дать понятию свой маленький тип |
| Повторные switch | один и тот же разбор по типу в нескольких местах | полиморфизм или одна общая карта |
| Дробовик | одно логическое изменение — правки по всему диффу | собрать изменяющееся вместе в один модуль |
| Расходящееся изменение | один файл правится по нескольким несвязанным причинам | разделить: модуль меняется по одной причине |
| Спекулятивная общность | абстракции и параметры под то, чего спека не просит | удалить, вернуть инлайн до появления нужды |
| Цепочка сообщений | длинная навигация `a.b().c().d()` | спрятать обход за один метод первого объекта |
| Посредник | класс или функция, которые только делегируют | убрать, звать цель напрямую |
| Отвергнутое наследство | наследник игнорирует или переопределяет почти всё | композиция вместо наследования |

### 5. Свести

Показать два отчёта под заголовками `## Стандарты` и `## Спека`, каждый в своей приоритизации:

```
## Стандарты
🔴 BLOCKING
- file.py:42 — <нарушение>. Правило: <CORE_PRINCIPLES §X / #D-XX>. Предлагаемое: <как>.
🟠 IMPORTANT
🟡 NIT (включая запахи — они всегда суждение)

## Спека
🔴 НЕ СДЕЛАНО / СДЕЛАНО НЕВЕРНО
- <требование> — цитата из acceptance. Что в диффе вместо.
🟠 ВНЕ ЗАПРОСА (scope creep)
- <что добавлено сверх> — anti-scope говорит: <цитата>

Итог: Стандарты — N находок, худшая <…>. Спека — M находок, худшая <…>.
```

**Не сливать оси и не выбирать между ними победителя** — это и есть переранжирование, которое разделение предотвращает.

### 6. Что дальше

Красное по любой оси — чинить до merge. Спорное — вынести Антону через A/B/C. Риск 🟢 и правка мелкая — хватит одной оси Стандарты, вторую не гонять (бережём лимит).

Каждое утверждение ревьюера должно быть проверяемым: факт о коде — `файл:строка`; ссылка на правило — `CORE_PRINCIPLES §X` / `#D-XX`; результат проверки — точная команда и её вывод. Нет опоры — помечать гипотезой, не фактом.
