# Обновление чек-пойнта

Фактические изменения для записи (собраны автоматически):

- Ветка: !`git branch --show-current`
- Коммиты с последнего тега: !`git log $(git describe --tags --abbrev=0 2>/dev/null)..HEAD --oneline 2>/dev/null || git log --oneline -10`
- Файлы, затронутые в этих коммитах: !`git diff --name-only $(git describe --tags --abbrev=0 2>/dev/null)..HEAD 2>/dev/null | head -40 || git diff --name-only HEAD~10..HEAD 2>/dev/null | head -40`
- Незакоммичено сейчас: !`git status --short`
- Раскладка чек-пойнта: !`ls CHECKPOINT_*.md 2>/dev/null || echo "нет файлов CHECKPOINT_*"`

Подсказка от меня (если дал): $ARGUMENTS

## Куда что писать

Посмотри на список файлов выше — от него зависят адреса записи.

**Один `CHECKPOINT_CURRENT.md`** (обычный случай): всё пишется в него, разделы §1–§10 на месте.

**Рядом лежат `CHECKPOINT_DEBT.md` / `CHECKPOINT_API.md` / `CHECKPOINT_ARCHIVE.md`** — чек-пойнт разложен по жизненному циклу, потому что перерос бюджет старта. Тогда адрес записи определяется **типом факта**, а не тем, какой файл открыт:

| Факт                                           | Файл                    | Раздел                  |
| ---------------------------------------------- | ----------------------- | ----------------------- |
| Состояние, закрытое в сессии, следующая задача | `CHECKPOINT_CURRENT.md` | §1 · §2.3 · §3 · §8     |
| Долг, баг, риск, отложенное                    | `CHECKPOINT_DEBT.md`    | новый `[DBT-NNN]`       |
| Контракт endpoint, миграция                    | `CHECKPOINT_API.md`     | §5 · §4                 |
| Закрытое — из любого файла                     | `CHECKPOINT_ARCHIVE.md` | раздел по происхождению |

При раскладке в §4/§5/§7 CURRENT остаются **заголовки со строками-указателями** — это не заглушки под удаление. И SessionStart-хук, и `validate_checkpoint.py` читают раздел как «от `## N.` до `## N+1.`», и пропавший заголовок заставит их молча отдать файл до конца. **Заголовки §1–§10 не убирать и не перенумеровывать** — это верно в обоих случаях, с раскладкой и без.

## Твоя задача

Обнови **осмысленно** (не дословно копируя git-лог):

1. **§1 Текущее состояние** — дату обновления; при необходимости прогресс/итерацию.
2. **§2.3 Закрыто** — что реально завершено в этой сессии (по коммитам выше).
3. **§3.3 Завершено в итерации** — перенеси выполненные задачи из §3.2.
4. **Миграции** — §4 (при раскладке — `CHECKPOINT_API.md` §4, а в CURRENT §4 поправь строку-указатель, если сменился head).
5. **Endpoints** — §5, если контракт менялся (при раскладке — `CHECKPOINT_API.md` §5).
6. **§8 Следующая микро-задача** — ПЕРЕПИШИ под текущий момент: ультра-конкретно, что делать в следующем чате (файлы, acceptance, ссылки). Это самый важный раздел. Держи здесь только **активные** блоки.
7. **Новый долг/риск** — §7. При раскладке: очередной `[DBT-NNN]` в `CHECKPOINT_DEBT.md` (номер = максимальный в DEBT ∪ ARCHIVE + 1); если он 🔴/🟠 — добавь строку-ссылку в срез CURRENT §7 и обнови счётчики, а перестал быть блокирующим — убери строку, сам пункт остаётся в DEBT.

## Ротация — закрытое не остаётся в рабочем файле

Тем же прогоном, а не «когда-нибудь». Именно накопление закрытого превращает чек-пойнт в файл, который не читается за один вызов:

- §8: исполненный или замещённый блок (🟢/✅/⚪/⛔, «прежняя запись») — из активных вон. Остаются только активные.
- §1: записи прошлых дат. Остаются свежая дата + структурные поля (Итерация/Прогресс/Веха/Статус).
- §2.3: закрытое прошлыми сессиями.
- Долг, помеченный закрытым, уезжает при **следующем** `/checkpoint`, не сразу: одна сессия должна увидеть, что он закрыт.

Куда именно уезжает: при раскладке — в `CHECKPOINT_ARCHIVE.md` (append-only, дословно, ID сохраняется); без раскладки — в архив итерации `CHECKPOINT_ITERATION_N.md` по правилам playbook.

Если чек-пойнт уже разбух и разбор вручную выходит объёмным — не сочиняй перенос руками, есть скрипт:
`python .claude/scripts/rotate_checkpoint.py --session-hashes <хеши> --out-dir <tmp>` (dry-run; словари разметки в его шапке настраиваются под проект, он же доказывает целостность двумя проверками).

Обновляй разделы целиком (не патчами). Если решение архитектурное — напомни мне завести
запись в `DECISIONS.md`. После правки прогони `python .claude/scripts/validate_checkpoint.py`
и покажи короткое summary: что изменил и в каком файле.
