# Карта тех-долга

## Маркеры в кодовой базе

TODO / FIXME / HACK / XXX по проекту (без зависимостей и сборок):

!`grep -rnE "(TODO|FIXME|HACK|XXX)" --include="*.kt" --include="*.kts" --include="*.swift" --include="*.py" --include="*.ts" --include="*.tsx" --include="*.js" --include="*.jsx" --include="*.go" --include="*.dart" . 2>/dev/null | grep -vE "node_modules|/build/|/dist/|/.venv/|/venv/|/.gradle/" | head -60`

Где живёт реестр: !`ls CHECKPOINT_DEBT.md 2>/dev/null || echo "раскладки нет — реестр в CHECKPOINT_CURRENT.md §7"`

## Задача

1. Прочитай реестр открытого долга: `CHECKPOINT_DEBT.md`, если он есть (тогда у каждого пункта есть ID `[DBT-NNN]` — ссылайся по ID, а не по формулировке, она может измениться; срез 🔴/🟠 в `CHECKPOINT_CURRENT.md` §7 отдельно читать не нужно, это те же пункты по ссылке). Иначе — §7 из `CHECKPOINT_CURRENT.md`.
2. Сведи воедино: маркеры из кода выше + пункты реестра. Убери дубли — `TODO(DBT-NNN)` в коде и есть тот пункт, а не отдельная находка.
3. Сгруппируй по серьёзности и предложи приоритет:
   - 🔴 **blocking** — мешает релизу/ломает инварианты, чинить в текущей итерации
   - 🟠 **important** — стоит закрыть до следующей вехи
   - 🟡 **nice-to-have** — бэклог
   - **без маркера** — исторические записи, серьёзность не проставлена. Не присваивай её молча: предложи и спроси.
4. Для каждого крупного пункта предложи, в какой итерации (см. `ROADMAP.md`) его реалистично закрыть.
5. Спроси, не внести ли что-то из найденного в реестр, если там этого ещё нет (при раскладке новый пункт = очередной `[DBT-NNN]`, номер = максимальный в DEBT ∪ ARCHIVE + 1).

Только анализ и предложения — код не трогаем.
