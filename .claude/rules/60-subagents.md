## 12. Субагенты — делегирование (`.claude/agents/`)

Субагенты — изолированные ревьюеры со своим контекстом: делегируешь им «шумную» работу (чтение всего diff, прогон тестов, картирование кода), а основной тред остаётся чистым и видит только итоговый вердикт. **Все они read-only**: находят и описывают, но не правят — правки делает основной тред (где работают хуки-предохранители из §10). Это автоматизация приёма «ревью в свежем чате».

**Что доезжает до субагента.** `CLAUDE.md` и `.claude/rules/` грузятся — правила протокола повторять в брифе не нужно. История разговора, прочитанные файлы и вызванные скиллы — нет: контекст у него свой, с нуля. Встроенные `Explore` и `Plan` не грузят даже `CLAUDE.md` — им всё нужное кладут в промпт при делегировании.

Автоконтекст сессии субагент тоже не видит, поэтому раскладку канона ему сообщает хук `subagent-context.sh`. Остальное — в брифе: что смотреть, откуда брать канон, по какой оси отчитываться. Бриф не пересказывает задачу, он ограничивает поиск.

**Потолки.** Одновременно работающих субагентов — 20 (меняется `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`); сверх лимита запуск отказывает, и повторять его не нужно. Отдельно действуют потолок общего числа за сессию и потолок глубины вложенности. Форк текущего разговора — `/subtask`, он наследует контекст вместо чистого старта и лимитом не блокируется. Управление субагентами — файлами в `.claude/agents/`: `/agents` с версии 2.1.198 мастер не открывает.

| Субагент            | Когда делегировать                                           | Модель |
| ------------------- | ------------------------------------------------------------ | ------ |
| `code-reviewer`     | Задача готова, перед merge — по одной оси на вызов: Стандарты или Спека | sonnet |
| `test-runner`       | «прогони тесты / что падает» — диагностика во время работы   | sonnet |
| `security-reviewer` | Diff трогает auth/платежи/данные/секреты/инфру (VPN, ФЗ-152) | sonnet |
| `design-reviewer`   | Менялся UI — суждение поверх токен-хука (состояния, a11y)    | sonnet |
| `bug-investigator`  | Баг-репорт/скриншот — петля обратной связи, затем корень; НЕ чинить без «ok». Работает по скиллу `diagnosing-bugs` | sonnet |

Правила делегирования:

- **Масштаб → церемония (оцени ДО делегирования).** Тривиально (1 шаг, решение очевидно) → делай напрямую, без интервью и спеки. Средне (одна фича, 2–4 неочевидных решения) → ≤3 точечных вопроса + краткая спека. Крупно (несколько частей или подсистем) → полный порядок: интервью → спека → делегирование → проверка. **При сомнении между уровнями — бери уровень выше**, понижай только по явному «это мелочь».
- **Перед merge нетривиальной задачи** — `code-reviewer` двумя вызовами, по оси на каждый; затронут security-периметр — ещё `security-reviewer`; UI — `design-reviewer`. Параллельно.
- **Оси не сливать.** Стандарты и Спека отчитываются раздельно: в общем списке сильная сторона маскирует слабую, и «сделано красиво, но не то» тонет среди замечаний по стилю.
- **Параллельный build-fan-out — только после утверждённой спеки или плана.** Ревью-субагенты read-only, их можно параллелить всегда. Запускать несколько агентов, которые пишут, до явного «да» на спеку — нельзя: без общего канона каждый гадает по-своему, результаты расходятся, лимит горит на переделках.
- **Стоимость.** Субагенты тратят кратно больше токенов (свой контекст у каждого). Не звать на тривиальное. Для поиска «где это лежит» — встроенный `Explore`, он дешевле и умеет фан-аут.
- **Вердикт субагента — вход для основного треда**, не финал: blocking-замечания исправляешь, спорные выносишь Антону через A/B/C.
- Конфликта с хуками нет: `test-runner` диагностирует по запросу, Stop-гейт `gate-tests` проверяет на завершении; `design-reviewer` судит, хук `design-check` ловит хардкод механически.
