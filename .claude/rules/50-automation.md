## 10. Автоматизация `.claude/` — хуки, команды, скрипты

Часть протокола обеспечивается машинно. Claude должен знать об этом и **не дублировать руками то, что делает автоматика**, и **не сочинять бойлерплейт, для которого есть скрипт**.

### 10.1. Хуки (срабатывают сами, см. `.claude/settings.json`)

| Событие                      | Хук                           | Что делает                                                                       |
| ---------------------------- | ----------------------------- | -------------------------------------------------------------------------------- |
| SessionStart                 | `session-start-context.sh`    | Кладёт в контекст ветку, коммиты, CHECKPOINT §8 и §7, PORTFOLIO, цель, раскладку канона |
| SubagentStart                | `subagent-context.sh`         | То же о раскладке канона — субагенту, который автоконтекста не видит             |
| PreToolUse (Edit/Write)      | `guard-files.sh`              | Отклоняет правку файлов из `.claude/protected-paths.txt` (= CHECKPOINT §10)      |
| PreToolUse (Bash)            | `guard-bash.sh`               | Отклоняет деструктивные команды (rm -rf /, force-push в main, DROP/TRUNCATE…)    |
| PreToolUse (Bash/Edit/Write) | `guard-highrisk.sh`           | Спрашивает разрешение на действия из `.claude/high-risk-patterns.txt`            |
| PostToolUse (Edit/Write)     | `format-after-edit.sh`        | Автоформат: ktlint / black+ruff / prettier / swiftformat                          |
| PostToolUse (Edit/Write)     | `design-check.sh`             | Проверяет дизайн-токены (см. §11)                                                |
| Stop                         | `gate-tests.sh`               | Тесты в фоне; будит только при падении                                            |
| Stop                         | `gate-quality.sh`             | Линт и типы в фоне; будит только при падении                                      |
| Stop                         | `gate-goal.sh`                | Мягкая сверка с GOAL на существенном ходе — напоминанием, не блоком               |
| Stop                         | `gate-security.sh`            | Разовое за сессию напоминание, если правки задели security-периметр               |
| SessionEnd                   | `session-log.sh`              | Пишет журнал сессии (страховка от забытого чек-пойнта)                            |
| вручную                      | `scheduled/memory-hygiene.sh` | Гигиена ai-memory: свежесть PORTFOLIO, размер JOURNAL, дубли заголовков           |

Следствия для поведения:

- **Отказ предохранителя приходит решением с причиной.** Причина видна в диалоге разрешений — читать её, а не гадать. Обходить нельзя: сказать Антону.
- **Запрос разрешения от `guard-highrisk` не обходится накопленными разрешениями** — это устройство, а не помеха. Совпало правило — значит решение принимает Антон.
- **Гейты тестов и качества не держат завершение хода.** Они уходят в фон и будят при падении. Отсутствие красного в момент «готово» не означает, что тесты прошли, — означает, что они ещё идут.
- Автоформат причесал файл — это не «чужие правки». Свои держать минимальными и в стиле проекта, форматтер добьёт мелочи.

### 10.2. Команды (вызывает Антон или Claude по делу)

| Команда       | Когда                                                                         |
| ------------- | ----------------------------------------------------------------------------- |
| `/checkpoint` | Обновить `CHECKPOINT_CURRENT.md` по реальным изменениям сессии                |
| `/gate`       | Задача доведена, готовится merge: риск по путям → ревьюеры → вердикт по двум осям (Стандарты / Спека) |
| `/impact`     | Пересматривается `#D-XX`, меняется сущность или US — обратная карта зависимостей |
| `/debt`       | Карта тех-долга: TODO/FIXME по коду + реестр долга (§7 или `CHECKPOINT_DEBT.md`) |

Команды `/resume`, `/commit`, `/propose`, `/apply` удалены 2026-07-26: за пять месяцев ноль вызовов. `/resume` дублировал SessionStart-хук, `/commit` проигрывал прямому `git commit` со счётом 675:3, change-юниты `/propose`→`/apply` не создавались ни разу.

### 10.3. Скрипты — композировать, а не сочинять (`.claude/scripts/`)

Когда задача требует типового каркаса — вызвать скрипт и дописать логику, **а не генерировать каркас с нуля**:

| Нужно                                                 | Скрипт                                                              |
| ----------------------------------------------------- | ------------------------------------------------------------------- |
| Скелет Alembic-миграции                               | `new_migration.py "описание"`                                       |
| Скелет Compose-экрана (состояния empty/loading/error) | шаблон `scripts/templates/Screen.kt.template`                       |
| Проверить заполненность CHECKPOINT                    | `validate_checkpoint.py` (он же — инварианты раскладки, если она введена) |
| Разложить разбухший чек-пойнт по жизненному циклу     | `rotate_checkpoint.py` (dry-run по умолчанию; словари под проект)   |
| Проверить дизайн-токены вручную                       | `check_design_tokens.py --tokens .claude/design-tokens.json <путь>` |
| Оценить риск diff → каких ревьюеров звать             | `assess_risk.py` (или команда `/gate`)                              |
| Проверить, что ссылки в документах не врут            | `audit_refs.py <путь>`                                              |
| Разложить обвязку из шаблона по проектам              | `sync-harness.sh` (в шаблоне; `--check` по умолчанию)               |

## 13. Эвалы — измерять, а не угадывать (`.claude/evals/`)

После смены модели, правки правил, playbook или субагента **поведение системы может незаметно ухудшиться** — был реальный шестинедельный регресс Claude Code, который команды без эвалов ловили «на ощущениях». Эвалы дают факт вместо ощущения.

- **Что это:** набор golden-задач на реальном коде с объективными критериями (компилируется / паттерн есть / токен использован / файл создан) — не «ответ хороший», а проверяемое да/нет.
- **Ядро — три кейса** (`01-surgical-edit`, `02-no-overengineering`, `03-checkpoint-protocol`): гонять всегда, они дешёвые. Остальные — по случаю: `04-design-tokens` при UI-правках, `05-grill-on-fork` и `06-avoid-ai-writing` при правке соответствующих скиллов. Набор, который дорого гонять целиком, не гоняют вовсе — а негоняемый эвал хуже отсутствующего, потому что создаёт видимость страховки.
- **Когда гонять:** сменил модель; поправил правила или playbook; добавил хук/субагента; «кажется, стало тупее»; раз в месяц.
- **Как:** `python .claude/evals/run_evals.py` (сравнит с baseline); `--baseline` — записать эталон; `--case <id>` — один; `--dry-run` — без вызова модели.
- **Регрессия** (раньше проходил, теперь нет) → раннер вернёт ненулевой код и список: повод откатить изменение или чинить правило.
- **Перерос:** если кейс проходит без твоего правила или скилла — правило, возможно, лишнее.

Расширяй набор, когда ловишь реальный промах: добавь его новым кейсом, чтобы не повторился.

## 14. Эффективность контекста и рутины (для своих продуктов/инфры)

Применяется к **тому, что ты строишь** (боты, API) и к фоновой автоматизации — не к работе Claude Code над проектом.

- **Prompt caching ≥ 80% hit rate** в проде агентов: стабильный префикс (системный промпт/инструменты байт-в-байт), не держать неиспользуемые схемы и сырой вывод инструментов. Мерить — `.claude/scripts/cache_report.py`. Детали — `playbook/token-efficiency.md`.
- **Форма данных:** в tool-выводах markdown вместо JSON, без лишних полей и таймстемпов (кейс −66% токенов). JSON — только где код реально парсит.
- **Рутины по расписанию** (`.claude/scheduled/`): на Windows cron нет — `/loop` в сессии, планировщик заданий, либо канарейка в `SessionStart`. Обёртки под cron удалены 2026-07-26 после нуля запусков.
- **Лимиты подписки** (если работаешь на Max/Pro, а не API): расход 5h/недельного окна не виден напрямую — мерь через `/usage` и `/cost` в сессии или `.claude/scripts/usage_check.sh`. `cache_report.py` — для API-ботов, где платишь по токенам; `usage_check.sh` — для подписочной dev-работы.
- **Уроки — два уровня.** Проектные — пакетный `LESSONS.md` (узкое для этого проекта). Портфельные практики и грабли — `~/ai-memory/LESSONS.md` (переносимое между проектами). SessionStart подтягивает заголовки обоих. Когда и куда фиксировать (с подтверждением, не авто) — `AGENTS.md §9`.
